# 合理性保障：四层约束链 + 对账闭环

> 本文件为「新团队初始化包」快照副本（snapshot: 2026-09-13），泛化自来源仓库机制库（旧版本文档已清理，本文件为事实源）。

> 机制前提（如实说明）：场景判断与 skill 选择是**模型概率判断**，给不了硬保证；合理性靠四层约束链让不合理判断"无处藏身"，靠每轮对账闭环持续收紧。

| 层 | 名称 | 机制 | 负责人 |
|---|---|---|---|
| ① 规则层 | 查表 | 决策表（02-场景决策表.md）固化场景→skill→角色，选择可对账、偏差当场可见 | 指挥官 + 文档 |
| ② 契约层 | 留痕 | 委派指名 skill + 产物标注 → 每环有可审计指纹 | 指挥官委派指令 |
| ③ 校验层 | 独立 | CodeReview **fresh 上下文**三轴审查（必要性/可行性/风险），不带指挥官判断结论；方案硬伤在 Reviewed 前被独立揪出 | CodeReview（只读） |
| ④ 门禁层 | 人闸 | Reviewed 人批（唯一写入者=指挥官）+ QA 门禁 + 状态机不可跳步 | 需求方 + 状态机 |

**对账闭环**：每完成一个需求加一步流程对账——实际走的链条 vs 02-场景决策表.md 预测；偏差（误判 / 断链 / 表不适用）记入复盘，下一轮修正决策表或 SOUL。

**三条诚实边界**：① 看不到被委派 bot 是否真调用了 skill（会话内部），契约层留痕是间接验证的闭环关键；② 调了 skill ≠ 做得好（skill 是提示词非程序），质量终审押在对抗审查 + QA 两道独立校验；③ 场景判断是概率，规则层写得越具体，"我认为"占比越低。
