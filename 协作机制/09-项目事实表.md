# 项目事实表（占位符 → 实值）

> 本文件为「新团队初始化包」快照副本（snapshot: 2026-09-13），泛化自来源仓库机制库（旧版本文档已清理，本文件为事实源）。
> 初始化脚本（初始化项目.bat）会复制本表到项目 `协作机制\` 并做全局占位符替换：**必替项**由用户输入推导后自动替换；**保留待手工项**由新团队按初始化包教程块⑥ 占位登记表填写。下表"实值"列在初始化后即为本项目实际值。

| 占位符 | 实值（初始化后） | 替换级别 |
|---|---|---|
| `OMB` | 用户输入的项目显示名 | 必替（bat） |
| `D:\OpenMausBot` | 用户输入的项目根绝对路径 | 必替（bat） |
| `omb` | 由项目名推导的小写 slug（仅 ASCII 字母数字、连续分隔符合并、首字符字母数字、空回退 `project`） | 必替（bat） |
| `D:\OpenMausBot\.agents` | `D:\OpenMausBot\.agents`（下含 `skills/` = Matt 技能库、`product-workflow-suite/` = 海天套件） | 必替（bat） |
| `D:\OpenMausBot\切片\<需求短名>\` | 需求切片目录，默认 `D:\OpenMausBot\切片\<需求短名>\`（海天命名：clarify.md / prd.md / technical-solution.md / development-plan.md / test-cases.md / build-verification.md / qa-verification.md + 证据截图） | 必替（bat，模式替换保留 `<需求短名>`） |
| `协作机制/README.md` | `协作机制/README.md`（机制库索引） | 必替（bat） |
| `协作机制/06-技术栈与部署.md` | 项目验证 skill：落地时从海天 `product-test-automation` / `product-wrap-up` 引用测试命令；项目专属验证 skill 待第一个需求闭环后沉淀 | **保留待手工** |
| `D:\OpenMausBot\.scratch\<feature>\` | 本地 markdown（`D:\OpenMausBot\.scratch\<feature>\`，Matt 体系默认支持，无需 GitHub）——纯过程区（日志/草稿/演练原稿），gitignore，整目录可随时删除；验证证据落切片入库 | 条件替（bat，本地 markdown 模式） |
| `/.local-credentials.env` | 凭据文件模式（禁读边界）：初始化后由新团队自行定义文件名与 gitignore 条目（见初始化包教程块⑥） | **保留待手工** |
| `OMB 团队` / `沿用上游 OpenMausBot LICENSE（见仓库 LICENSE / LICENSING.md）` | botmrr 团队模板元数据：初始化后由新团队填写 | **保留待手工** |

**导入后必做 5 项：**
1. 每个 bot 的 cwd 设为 `D:\OpenMausBot`（团队包不携带 cwd，必须手工设置）；
2. 按 02-场景决策表.md 映射表确认各角色可用的技能来源（cwd 直读 `.agents` 即可，无需导入 OMB）；
3. 如需要 OMB 级 skill（跨项目通用验证纪律等），用 skill 导入（GitHub 来源）或 `skill_manage` 创建；
4. 状态看板房间：团队模板已带 slug 驱动的状态看板房间（初始化后见项目 `文档\团队模板\<slug>-team.botmrr.md`，只广播项目需求）；
5. 检查 routine `error-log-watch` 的日志路径规则（07-错误日志监控.md）与调度参数是否符合预期（默认 paused）。
