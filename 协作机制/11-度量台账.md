# 度量台账（切片量化复盘）

> 本文件为「新团队初始化包」快照副本（snapshot: 2026-09-13），泛化自来源仓库机制库（旧版本文档已清理，本文件为事实源）。
> 机制依据：01-需求分级.md 原则 7（记数定义）+ 原则 12（复盘机制，v2.1）+ 原则 13（时间线记录，v2.3）。
> **聚合点**：每切片 `.workflow-state.json` 的 `metrics` 三数 → 本表一行。
> **时间线**：每切片 `.workflow-state.json` 顶层 `timeline` 数组为环节耗时唯一事实源（v2.3）；本表「环节耗时」列为聚合引用。指挥官委派时实时记 `started_at`、阶段收尾记 `ended_at` + `duration`。
> **记录责任**：指挥官（Reviewed 写入时记 `lead_time_to_reviewed`；收到 QA 判定后 24h 内补记 `rework_count` / `qa_first_pass`——QA 是只读 bot 不写状态机）。
> **复盘节奏**：切片级即时记数 + 每 3~5 个切片或每月一次复盘（指挥官主持、与需求方对齐；文档型任务不广播）。
> **阈值信号**：M/L 级 `lead_time_to_reviewed` > 3 天须写原因；`rework_count ≥ 2` 须写根因；`qa_first_pass = false` 必须写缺陷摘要。
> **复盘产出**：保留 / 调整 / 废弃某机制 → 写进《10-优化方案决策.md》→ 决策表（02-场景决策表.md）据此刻意修订。

## 复盘记录

### 复盘 1（首个切片收尾时的机制教训，快照自来源仓库经验）
- **发现**：首个走完 8/8 流水线的切片 `.workflow-state.json` 无 `metrics` 字段——定义（原则 7）与执行脱节：文档写了记数时机，但没有明确「谁来记、何时记」，导致流水线全程无人落数。`lead_time_to_reviewed` 因未记录澄清起点时间戳标「数据缺失」，无法回溯。
- **行动**：
  1. 补记：`qa_first_pass` / `rework_count`（依据实现/构建/QA 记录）；`lead_time_to_reviewed` 标「数据缺失」。
  2. 新增 01-需求分级.md 原则 12（复盘机制：聚合点 / 节奏 / 阈值 / 产出物 / 记录责任与纪律），明确 QA 判定后 24h 内补记，杜绝空 metrics 切片。
  3. 新建本台账作为聚合点。
- **状态**：已闭环（教训通用：**定义与执行之间要有人负责落数**）。
