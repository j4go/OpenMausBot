# Product Wrap-Up（收尾检查）

> 套件成员。版本见根目录 `VERSION`。

## 定位

收尾 = 走完 product-workflow 既有契约（阶段批准门禁、输出契约、双视图契约、H5 图示契约）的**检查点**，不是新流程。检查不通过时，不得宣布完成、不得进入下一阶段、不得切换切片。

## 触发时机

以下任一时刻，先跑本 skill 再继续：

1. 请求用户评审当前阶段产物前
2. 宣布「完成 / 通过 / 已修复」前
3. 切换或插入切片前
4. 修改 / 修复后向用户汇报前

## 证据铁律

**无本轮新鲜验证证据，不得宣称测试/门禁已通过。** 用户豁免编码时：完成标准是责任人和风险已写入 `develop.md` 与 state，不是测试绿。

Gate Function（每项「完成」声明必经五步）：

1. **IDENTIFY**：哪条命令 / 检查能证明这条声明？
2. **RUN**：本轮完整执行——「之前跑过」「应该能过」不算证据。
3. **READ**：读完整输出、退出码、失败数，不只看结论行。
4. **VERIFY**：输出是否支持声明？不支持 → 如实报告实际状态。
5. **ONLY THEN**：才允许宣告完成。

失败对照（禁止的情况）：

| 声明 | 需要 | 不足够 |
|---|---|---|
| 测试通过 | 本轮 test 输出 0 失败 | 之前跑过 / 应该能过 |
| 看板已同步 | md/state 已更新；打开壳能看到新内容 | 只口头说同步 |
| 文档已更新 | 受影响文档 diff 确认 | 「已同步」口头声明 |
| Bug 已修复 | 重跑原始症状通过 | 代码改了就算好了 |
| 阶段已批准 | 用户明确批准记录 | AI 自行推进 |

## 收尾清单

逐项执行，全部通过才可宣布完成。无法执行的项记 `skipped` / `not-run` 并附原因，**不得伪造结果**。

### A. 状态一致性

- [ ] `.workflow-state.json` 已过 `node product-workflow/scripts/validate_workflow_state.mjs <工作流目录>`：无错误、无 BOM，`current_stage` 与各阶段 status 符合实际。`run_mode=lite` 时还必须通过 `validate_lite_slice.mjs <工作流目录>`
- [ ] 未批准阶段未标记 Reviewed；豁免项已写入 state 顶层 `waivers[]`，且看板显示「已豁免 · 未完成」（参照测试基建门禁规则）

### B. 产物完整性

- [ ] 当前阶段产物存在且达标：full 有 J-/US-/AC-/TC-/TASK- 追踪；lite 有短 PRD 的 AC 与短开发计划的 TASK 对照。有上下文、无 TBD/占位（见输出契约）
- [ ] 源头已更新（阶段 `*.md` + `.workflow-state.json`）；未为同步展示去改或提交看板 HTML。本轮改过源头的，已运行 `render_review_board.mjs`，`.review-board/index.html` 存在。工作流目录 `.gitignore` 已排除 `.review-board/`。
- [ ] PRD / 开发计划请求人批前，源头已有 `## 对抗审查`；有阻断发现时未请人按已通过批准
- [ ] 本轮已按公共契约 § 软件门户同步处理门户（`bound_project` 才上传）
- [ ] 进入实现前已按公共契约 § 开工前交付物核对
- [ ] 产物位于标准目录 `docs/product-development/YYYY-MM-DD-<主题>/`

### C. 文档回写与对照

- [ ] 受影响文档（prd / prototype / test-cases / technical-solution / development-plan）已同步本次变更
- [ ] 实现对照已批 PRD / 原型 / Wiki；字段和组件能在源码或 DDL 里找到（见 `../product-workflow/references/read-before-write.md`）
- [ ] **Wiki 约定逐条对照**（问题 #37）：从 Project Wiki / PRD / 原型提取本切片约定条款（组件复用、边界、接口、禁造字段），逐条给出「代码位置」或「未做 + 原因」；静默偏离不得宣称完成。偏离处理只有两种：改代码对齐，或回写 wiki 并经用户批准。逐条对照表写入验证报告。
- [ ] 涉及切片时，切片总览表 `slices-overview.md` 已更新

### D. 证据与汇报

- [ ] 验证命令已本轮执行，输出留档（存 `wrap-up/` 或产物目录）
- [ ] 验证报告已落盘 `wrap-up/<阶段或切片>/verification.md`（模板见同目录 `references/verification-report-template.md`）
- [ ] 收尾汇报包含四要素：文件变更 / 依据编号 / 验证命令与结果 / 遗留风险

## 失败处理

收尾不通过时按序处理，**不降级通过**：

1. **诊断**：定位是状态 / 产物 / 文档哪一类问题
2. **修复**：重建看板 / 补产物 / 同步文档 / 补验证，针对根因改
3. **重验**：重新跑收尾清单，最多迭代 3 轮
4. **仍不过**：如实向用户报告阻塞项与原因，等待用户处置

## 汇报格式

按验证报告模板输出；用户只关心结论时，用四要素一句话：

```text
完成。<阶段/切片> 收尾通过：改 <文件>（依据 <编号>），验证 <命令> <结果>，遗留 <风险>。
```

## 与既有契约的关系

- 本 skill 引用但不重复 product-workflow 的阶段批准门禁、输出契约、双视图契约、H5 图示契约；
- 本 skill 是 AGENTS.md「文档回写义务」的强制检查点，切片切换须过本检查（见 AGENTS.md 执行纪律）。
