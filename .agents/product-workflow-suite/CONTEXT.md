# Product Workflow

给编码助手跑需求切片的工作流套件。本文件只收领域用词。现场裁剪（如海天）不是套件名。

## Language

**遗留套件**：
项目没有测试，或有测试但常红、废弃、修不完。走增量覆盖，不为追覆盖做可测试性大重构。
_Avoid_: 遗留系统（太宽，健康套件里的旧模块也会被误伤）

**健康套件**：
测试能绿，可以当回归。可走可测试性重构（Option A）。

**增量覆盖**：
只给本切片碰到的、能测的变更加测试。未改动的旧代码不回填。尽量不改生产结构、不引入大风险。

**新增代码**：
本切片新写的函数、类型或文件。必须可测，必须有单测。写的时候不要复制遗留的不可测结构。
_Avoid_: 整个 diff（里面常混着改动过的遗留行）

**可测试性挑战**：
本切片碰到、不加结构改动就写不出有意义测试的点。摊给用户决策，不静默排除，也不静默重构。

**抽出（sprout）**：
新行为写在可测的新函数或新类型里，旧代码只加一行调用。这是保证新增代码有测试的默认做法，不是可测试性大重构。
_Avoid_: 抽出一层（太容易变成改调用链）

**外包（wrap）**：
在旧入口外包一层再测新层。会动调用链，必须用户批准。

**工作区**：
产品经理为某个项目准备的本地目录。空则按仓库地址拉取；已有 git 则跳过拉取。
_Avoid_: 开发环境（不包含装依赖、跑构建）

**对抗审查**：
请人批之前，用 `$product:review` 过规格、可判定、事实三轴。写进本阶段源头，不另开文件。
_Avoid_: 自评（写稿的人说没问题不算过）
