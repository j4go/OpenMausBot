## 和上一版比，现场会碰到的变化

| 你会碰到 | 这一版怎么用 |
|---|---|
| 对 AI 说「做个需求」，它自己从澄清一路跑到开工 | 连跑要你先点 `$product:workflow`。拿不准该点哪条，先 `$product:ask`：它只告诉你下一步点什么，不替你开跑。 |
| PRD 或开发计划刚写完，就让人批 | 先跑 `$product:review`。它看三件事：规格清不清、验收能不能当场判定、有没有对上仓库里已经存在的事实。过不了就停在 Draft，改完再请人批。 |
| 命令太长，记不住 `development-plan`、`start-implement` | 计划用 `$product:plan`，开工用 `$product:kickoff`（说 `$product:开工` 也行）。切片里的文件名还是 `prd.md`、`development-plan.md`、`start-implement.md`，这一版没改。 |
| 产品经理拿到空文件夹，不会自己 Git | `$product:init` 会问仓库地址，然后 clone。目录里已经有 git 就跳过。 |
| 软件门户还在用旧的 `limix workflow` / `limix onboard` | 按 Limix CLI 0.6.1：项目用 `limix project`，需求用 `limix requirement`。没装 CLI、或初始化时选了只要代码仓，后面阶段不会去调 limix。 |
| 交付件有的进 Git、有的要上传门户，对不齐 | 初始化时三选一：只要 git、只要门户、或两个都用。两个都用时，同一批人批过的源头既要已经提交，也要已经上传。 |
| 审查板 `index.html` 被当成交付件传到门户 | 活看板只写在切片下的 `.review-board/`。根上旧的 `index.html` 迁到 `.review-board/legacy/`。门户要看的 HTML 预览是 `prototype.html`。 |
| 遗留仓为了追覆盖率，大改不可测的老代码 | 覆盖率按这次改动算。新增代码要有单测。测不到的遗留行默认窄排除。 |
| 人标成 Reviewed 了，git 或门户还是旧的 | 开工前再核一次：适用产物是 Reviewed；在仓里则已提交；绑了门户则已上传。对不上就停。 |

## 装完对 Codex 说

1. 读本项目 `AGENTS.md`。
2. 连跑要你点名。拿不准点哪条，用 `$product:ask`。
3. 单测和 Git Hook 是建议，不挡编码。没跑通别标成已通过。
4. 复现问题带上版本号 haitian-pw-0.6.0。
5. 核一下来源：`node scripts/release-integrity.mjs verify --expected-version haitian-pw-0.6.0`。
6. 到客户项目根跑一次迁移（把套件安装夹换成实际路径）：

```bash
node "<套件安装夹>/product-workflow/scripts/migrate_suite.mjs" .
```

这会刷新章程托管块、把切片根旧 `index.html` 迁到 `.review-board/legacy/`、补看板、改原型回链。块外用户内容不动。若报章程冲突，先给人看差异，别直接覆盖。
