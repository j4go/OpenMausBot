## 事实门

**开门规则**：本轮新增、改写、摘要、引用或重新背书，且会影响理解、结论、操作或决策的外部可核主张，必须能指出支撑材料的具体位置（章节、段落、原句、数据行或实际测试记录）。适用对象包括数字、日期、引语、版本行为、因果、结论，以及身份或版本会影响判断的专名；核不到就标为线索或「（待核：缺什么）」。原样搬移只检查限定、上下文与来源没有断裂；只有搬移改变了范围或含义才重核事实。未触及的既有主张不因本轮写入自动开门。页面分类、作者判断、工作区决定和规范性要求不伪装成外部事实，应明确写成「本页判断」「本库约定」「内部规定」或同等口径。模型记忆、标题、摘要、聚合页、AI 输出、打不开的引文都只能作线索。

**风险档**

| 证据档 | 适用范围 | 核查要求 |
| --- | --- | --- |
| 高风险 | 涉及人身与医疗、法律责任、财产、权限与隐私、生产安全、人物责任、争议政治定性，或会直接驱动重大决策的关键结论 | 对影响结论的关键主张逐项核；关键数字、日期、引语与因果不得抽查替代 |
| 中风险 | 普通知识文章、技术比较、人物与事件叙事、论文和书籍解读 | 每个实质分节核查其实际存在且影响理解的主张；数字、日期、专名与因果只在本节确实出现时检查，不为达标制造材料 |
| 低风险 | 机械维护、个人记录、原始材料整理、无新增事实的结构调整 | 只检查改动没有制造新事实、改变限定或切断来源 |

拿不准时升一档；不得用更高档名义制造无关检索和形式化引用。

**主张与来源适配**

| 主张类型 | 优先证据 |
| --- | --- |
| 法规、政策、标准和产品声明的文本内容 | 对应官方原文；它只证明文本如何规定或发布者如何主张 |
| 软件参数、命令、API 与版本行为 | 当前版本的一手手册、发布说明，加必要的实际复现 |
| 性能、效果、采用率和方案优劣 | 可复现设定、独立评测或多方工程证据；厂商自报须就近标明且不单独推出普遍结论 |
| 历史事件、人物责任和社会因果 | 一手材料与匹配的高质量研究交叉印证；来源立场、可得性与统计口径分别说明 |
| 论文结论 | 论文原文、实验设定、复现、方法批评与后续研究 |
| 人物意图与自我评价 | 本人原话可证明其自述，不自动证明客观事实 |

证据强弱取决于与主张的适配、独立性、直接性和可复核性，不使用「一手材料永远高于二手材料」的单线排序。作代表方案或工具还须有实际采用、活跃维护、独立评测或权威引用；高热度不等于正确，试验品只在边界内提及。

**表达边界**：已证事实可直陈；主流但非定论写明证据强度；可靠分歧并列；作者推理和判断单独标识。不得把多源拼成任何一源都没说过的话，也不得用「据相关资料」隐藏来源缺口。

**时效**：以下仅是默认复核上限，不是有效性保证：软件版本／评测榜单／产品现状 90 天，法律政策／现职人员 180 天，史政社综述／人文知识页 365 天。发生新版本、政策修订、职位更替、论文撤稿、重大反证或链接失效时立即触发复核。纯历史事实无固定周期。机械维护不刷新也不触发整页时效复核；内容编辑只复核被重新陈述且存在时效风险的主张。快速变化主题的摘要以「截至 YYYY-MM-DD：」起头；无动态成分的页面不写「截至」。超期未核可继续非事实性整理，但须标「时效待核」并列出受影响的高风险主张。

**反证检查**：仅对因果判断、方案优劣、争议历史与政治结论、论文结果、产品性能及会显著影响决策的中心判断，主动查最强反例、复现、方法批评与后续逆转。反例若成立，应削弱、改写或撤回结论，不得预设它必然「不成立」。纯命令语法、简单描述事实、个人日志不制造假争议；反证过程默认作为内部检查，只在确有实质分歧时进入正文。

**引用与参考资料**：直接引语逐字核原文，包括怪字怪标点；转述保留限定；关键主张邻近给出来源。参考资料条目由可核题名、链接和括号说明组成，括号写清支撑正文何处及点开可核什么；只用编号列表，不收 AI 转述和聊天记录，同一 URL 不重列。排序只分：原始文献与官方文本 → 学术出版 → 机构与官方发布 → 报道访谈影音 → 个人材料与聚合页。聚合页只作导航，不单独支撑中心结论。

**常见失败与对策：**

- 凭记忆写数字 → 当场打开匹配来源；核不到就删去断言或标明待核。
- 把「可能」写成「是」→ 保留原来源限定；可考准的日期、人名、职衔与数字不写模糊值。「约」只用于穷尽来源仍不可考且已说明原因。
- 把厂商声明写成事实 → 标明「厂商自报／无独立复现」，再查独立证据。
- 为显得客观制造反方 → 只呈现可由材料支撑的实质分歧。
- 链接失效不试 → 本次实际使用的链接逐条试开；死链换官方存档、DOI、Internet Archive 或出版社书目页，换不到则保留完整书目并标「链接已失效·待补」。

## 体例门

**页型与首屏**：知识文章用 `**摘要**`；教程／操作指南／参考手册用 `**用途**`（1–3 句，标题已说清时可省）；纯汇总／索引用 `**导读**`；日志、清单、原始材料、数据登记与 ADR 不强制。一页只用一个首屏组件，不为形式完整制造空摘要；首行只写标签名，下面直接正文，不另设导言、本页定位、核心摘要或阅读说明。

- **摘要**：页面第一个块；用引用块整块呈现（行首 `>`，多行连续引用），不带任何图标或装饰。首行单独一行粗体 `**摘要**`。次行起正文用 3–6 句密实连续文字，首句必须是判断，依次点明对象是什么、靠什么材料、主张什么；不分行、不列条、不加 emoji；不写分节罗列、参考条目、待办清单、`最后更新`、AI 或转述来源说明、编辑元叙述。
- **用途**：与摘要同构（第一个元素、引用块、无图标、首行粗体 `**用途**`），1–3 句，说明读者能做什么或学会什么。
- **导读**：与摘要同构，最大三段、全文 200 字以内。范围必写，边界必写，使用前提有才写。
- **证据基础**：可选组件。只在核心主张的证据性质或最大未知会影响理解时使用；写在摘要引用块末行，以粗体 `**证据基础**：` 起头 1–3 句，不计入摘要正文句数。厂商数据就地标注。页末自发的「核查状态／证据边界」引用块一律并入首屏或正文对应主张附近。
- **目录**：md 无原生目录，优先用渲染器自动 TOC（GitHub、Typora、VSCode 等原生支持）；渲染器不支持时生成锚点链接清单（`[章节](#anchor)`）紧随首屏作为第二个块。实质 H2 ≥ 6 必写、≤ 5 不写；含完整 CLI／API／配置键清单的参考手册页不论标题数量都写目录。H3 和 `参考资料` 等固定结构标题不计。
- **收尾**：正文 → `## 参考资料`（若有，必须是最后一个内容分节）。全库不设 `## 下一步` 分节；知识文章和综述把待深挖写成正文末段的 2–4 个具体疑问句，个人待办另置一页或交任务系统。

**最后更新**：普通页面在参考资料后（或无参考资料时在正文末尾）可选一行 `---` 分隔，下一行写 `最后更新：YYYY-MM-DD`。日志、清单、原始材料与数据登记不强制。frontmatter 已有 `last_modified` 或类似自动属性的页面不重复手写。

**加粗闭合规则**：`**内容**` 的闭合 `**` 前是标点、后紧跟非空白且非标点字符时，不构成右侧定界（right-flanking），不能闭合为加粗。三类常见失效与正确写法见下表；开头 `**` 后紧跟标点（如 `**「允许」**`）不受影响。修复优先级：标签类（冒号移出 `**`）＞ 括号类与引号类（闭合 `**` 后补一个空格）。

| 失效写法 | 问题 | 正确写法 |
| --- | --- | --- |
| `**标签：**内容` | 闭合 `**` 前是 `：`、后紧跟文字 | `**标签**：内容` |
| `**xxx（yyy）**文字` | 闭合 `**` 前是 `）`、后紧跟文字 | `**xxx（yyy）** 文字` |
| `**"xxx"**文字` | 闭合 `**` 前是 `"`、后紧跟文字 | `**"xxx"** 文字` |

**速查表**：新页与完整整理／重构任务全量执行；机械维护只检查目标片段，除非发现会造成误读、泄密或结构损坏的高风险缺陷。标点规则只约束普通正文，代码、URL、标识符与逐字引语保留原形。表中未标 D 的是强制默认；D 项允许说明理由后偏离。

| 项目 | 全库统一写法 | 不得出现 |
| --- | --- | --- |
| 引号 | 直角引号「」，内层『』 | 普通正文使用弯引号或半角双引号 |
| 书名与作品名 | 中文《》；外文用 *斜体*；论文题名同外文例 | 用引号代替书名号 |
| 破折号与省略号 | ——、…… | 普通正文使用 `--`、`...`、`…`、`。。。` |
| 区间 | 连接号 –：`1986–2004`、`9–19 个百分点` | `1986-2004`、`1986~2004` |
| 并列与层级 | 中文并列用／；层级递进用 ·；流程箭头两侧留空格 | 半角 `/` 作中文并列；箭头无空格 |
| 中西文混排 | 中文与拉丁字母、数字间留一个半角空格 | `2000年ACM图灵奖` |
| 紧贴项 | 中文标点不留内侧空格；百分号和货币紧贴数值；拉丁量纲与数字留空格 | `（ 2018 ）`、`42.7 %` |
| 日期 | `YYYY-MM-DD` | `2026/7/25`、`2026.7.25` |
| 动态摘要首句 | `截至 YYYY-MM-DD：` | `截至2026-07-25：` |
| 摘要引用块 | 完整定式见本节「页型与首屏」 | 蓝底或带图标；索引页写「摘要」 |
| 标题层级 | 同页 H2 均为名词短语或均为动作短语；H3 必挂在 H2 下；缩写与英文行话首次面向读者出现时给出全称或中文释义 | H2 后直接 H4；同层标题语法混搭 |
| 标题命名 | 标题不含 emoji；新建页不设 emoji 标题 | 用 emoji 承载分节语义 |
| 目录（D） | 位置与门槛见本节「页型与首屏」 | 手写标题清单充当目录；目录与首屏之间夹正文 |
| 最后更新 | 见本节「最后更新」 | 正文中散落日期戳 |
| 引用块颜色 | 灰＝说明（摘要／用途／导读等外围说明，忽略也不出错）；绿＝已验证可用；黄＝注意与待核；红＝安全、法律、凭据或不可逆风险 | 装饰性彩色、同义异色、无标签的裸引用块 |
| 文字高亮 | 成稿零无意义高亮 | 遗留背景色标记 |
| 加粗 | 短引导标签、组件名、列表领句、表头关键词、术语首现 | 通段加粗、加粗嵌套行内代码 |
| 行内代码 | 文件名、路径、命令、配置键、flag | 把文件名伪装成普通链接 |
| 链接 | 可读标签，中文标点在括号外 | 裸贴 URL、无法解析的相对路径内链 |
| 表格（D） | 结构化比较才用；须有表头、无空列，普通表优先不超过 5 列 | 用表格代替论证；无表头 |
| 分隔线 | 正文中不用 `---`；页末 `最后更新` 前可用一行 `---`（特例）；frontmatter 的 `---` 是文件格式，不受此限 | 以分隔线切正文；页末无 `最后更新` 时也用 `---` 垫页脚 |
| 列表 | 同层符号一致；连续叙事不切成项目符 | `-`、`*`、`•` 混用 |
| 空块 | 成稿无空段落、空标题 | 独立 `<p />` 或空标题残留 |
| 体裁纯度 | 一种主导体裁，其他形式作功能块 | 两套并列且互不统属的阅读骨架 |

**标题与文风：**

- 标题关键词在前、角度清楚、可检索；正式页宜用「主题：关键限定或核心问题」。中文标题 16–24 字为常用范围，超过 32 字时优先把背景与副题移入首屏；正式书名、论文题名、法规全称、命令或配置键可例外。用户特意命名或改名会造成检索歧义时，先说明再改。
- 写法从人、事、物和动作落脚，让细节、对照、条件与后果承载判断；语言克制但信息完整，少用空泛评价形容词、官腔、营销腔和模板 AI 腔。句子可以短，但不省掉主语、对象、条件或因果。页面须脱离原对话独立可读。
- **术语注释**：英文术语首次出现时注中文释义，中文术语（不常见或有歧义）首次出现时注英文原文。格式：`英文术语（中文释义）` 或 `中文术语（English）`。只注读者不会一看就懂的术语，AI、API、Git、commit 等通用词不注。每篇独立——同一术语在不同笔记中首次出现时各自注释，不依赖读者跨笔记检索。已在正文中展开解释的术语可不重复括号注。
- 全库文风以本文件「反例对照」小节为标尺：从人、事、物、动作落脚，让细节、对照与后果承载判断，不靠形容词和评价腔。写足该交代的事实、概念、条件与结论，克制但不隐晦，不说半句让人猜；情绪和态度由措辞的分寸带出来，不靠堆砌。「白描」是想要的效果——信息完整、判断藏在细节里——不是模仿哪位作家的文风，也不刻意追求某种腔调。本条只守底线（去烂腔、去 AI 腔、去堆砌），不承诺文学高度，也不越界去模仿具体风格。

**图像与链接**：非汇总型知识页默认不增加无论证作用的工作区互链；承担论证或追溯作用的稳定知识对象可以保留文字引用。汇总、索引、父子层级以导航为核心，不得按「纯导航」删除。对外稿不依赖工作区内部链接，参考资料不以工作区页面代替外部证据。图片只在承载文字难以表达的信息时插入；每张图紧邻说明与来源，截图先脱敏，关键数字与判断同时写入正文。

**跨笔记零引用**：笔记正文不链接、不点名其他笔记（含「见 XX.md」式软引用）。每篇自足——读者只读本篇即可获得完整信息，需要的关键事实与判断直接写在本页。笔记之间的关系由「编号（0X-）＋目录架构（pi/ ／ claude-code/ 等）＋ README 索引」承载；README 导航表是唯一的跨笔记关系维护点，增删改笔记只动 README 与自身。例外：索引页、目录页、父子层级导航（如 packages 索引）可链接子项，因为它们本身就是目录而非笔记正文。

**编号即稳定 ID**：工具笔记的 `0X-` 编号是笔记身份与顺序的稳定标识——改标题、改正文都不动编号，只有「拆篇／合篇／换主题」才动编号。编号只用于自身命名，不作为跨笔记引用手段。

**汇总页**：纯汇总页只写收录与归属规则、分组结构与判准、阅读路径，不写背景综述，也不设 `## 参考资料`。索引兼笔记页按知识文章验收，索引只是受控功能块。分节导读仅在分组 ≥ 10 且多数组各挂 ≥ 8 篇时允许。结构性导航块与入口必须保留。

## 保全门

**授权判定：**「评估、复盘、检查、审阅、给建议、列行动清单、看看如何优化」默认只读；只有对象明确的「直接修改、执行修订、按方案改、删除、移动、合并」才构成写入授权。用户明确授权重写、彻底修订或重构后，不再重复询问该范围内的结构删除，但附带副作用仍须单独判断。

**按模式验收：**

- 机械维护：只改目标片段；不顺带重命名、重排全文、清除图标、改 frontmatter 或重核未触及事实。
- 内容编辑：完整读取当前页，建立修改范围；新增、改写、摘要和重新断言的内容按事实门核查。
- 研究与新建：一次写到适用骨架的合格标准，不先交薄版。
- 结构与批量：先定范围和分母，再预览、备份、检查点、逐项失败记录与写后复扫。

**可直接改**：目标范围内的错字、标点、空段落、损坏格式、同页字面完全相同且保留一份的重复块、不改变原意的措辞，以及经本次事实门核实的事实错误。

**须先确认**：删除或归档整页、跨页合并、改变父子层级、改变主题归属、跨权限迁移、扩大共享、批量删除实质内容、不可逆转换；删除完整段落 ≥ 3 段、移除任一 H2、删除任一参考资料条目、整张表格或整个代码块。若某动作同时命中「可直接改」与「须先确认」，以后者为准；字面完全相同的机械重复块可在保留一份且有回退路径时例外。

**保真红线**：整理、迁移、格式化或等义改写后，正文字数低于原文 70%，或表格、代码块、命令示例、图片及说明、参考条目任一类减少，均是破坏性修改信号。摘要、明确删减或替换任务可按授权突破该信号，但须保留原页或可恢复版本，并在交付中说明有意省略或删除的范围。字数不低于 70% 也不证明保真，仍须核对独有信息。

**结构块红线**：当前工具无法完整表示的块（如嵌入脚本、复杂表格、特定插件语法）都不是普通导航文字。未明确针对这些对象授权时，必须原样保留其身份、属性和位置关系；不得用普通链接替代，不得因重排正文而删除、复制或重建。发现无法安全保真的结构块时停止相关写入并说明影响。

**附带副作用**：页面任务不得顺带修改其他文件的结构、frontmatter 属性、全局配置或共享设置，除非这些动作已在本轮范围内。发现其他页面缺少必要信息时只报告，不自行扩张修改范围。

**合并与去重**：跨页合并或只留一篇前，先逐条列出每页独有事实、日期精度、机构与职务全称、方法提示、边界、待核项、存疑引语、结构块及参考条目。迁入后回读成稿逐项勾核；全部落地后才处理旧页。旧页默认保留，删除或归档仍须明确确认。

**权限与敏感**：同权限或更窄的写入可以按任务执行；私密 → 共享受限／仓库公开等受众扩大必须在写入前取得本轮确认，并按目标读者脱敏。相同内部受众之间不因跨页而机械抹去有业务必要的人名和对象，但对外稿及更宽受众必须脱敏真实主机名、账号、密钥、内网 IP／网段、内部系统与工单编号、同事与第三方姓名。既有页面中的明文敏感值默认不自动删除，也不移动、复制或扩大受众。盘点、抽样与选页先使用标题和 frontmatter 等最小信息；明显可能含凭据的账号、登录或配置页，不作为通用质量样本，除非用户明确指定或任务必须读取。确需完整读取时，不在聊天、审计页或更宽受众位置复述敏感值。

**恢复与续接**：批量迁移须备份、预览、转换幂等、逐页检查点和写后全量复扫；事实改写走逐篇闭环。长任务把范围、分母、状态、已改、未改、风险与下一步写入当次明确的进度页。状态只取「待处理、已读取、已诊断、核查中、已修改待验收、已完成、受阻、跳过（说明原因）」之一；只有写入、核查、回读和复扫都完成后才标「已完成」。

**现有内容违规处理**：遇到已有内容违反本宪法时，遇改即改——只修正本次触及的部分，不主动发起全库扫查。用户明确要求全库整理时，按流程与交付的标准流程执行。

## 流程与交付

**轻量闭环**：适用于机械维护。载入目标 → 确认唯一修改点 → 小范围写入 → 回读修改结果 → 简短报告。不得为完成形式而生成五值执行头或全文诊断。

**标准闭环**：适用于内容编辑、研究与新建。定范围 → 判模式、页型、体裁、主专项、证据档与须确认项 → 完整读取当前页正文，子页和附件按相关度载入 → 诊断 → 按门禁核查 → 一次写到合格 → 反证检查 → 独立成读 → 写后复扫 → 交付。读取被截断时须补读；无法读取的子页或附件列出名称、数量与影响，未读内容不得进入成稿，也不得用同名材料替代。

反方审稿必须真正允许推翻原结论：写出最强替代解释，比较它能解释哪些材料；若它与原结论相当或更强，修改正文，不得把「解释它为何不成立」当成预设任务。独立成读是脱离当前对话阅读首屏与关键指代，确认页面不依赖聊天上下文。

**写后回读口径**：按预期差异逐条核对正文与结构；一次调用含多处编辑时，须确认每个编辑点都已落地。未生效且属于实质内容的编辑单独重试一次，仍不生效则记入未完成项。工具明确标为语义等价的表示层规范化不回改；代码语言、链接目标、属性值、块身份或正文含义发生变化，均不视为表示层差异。

**写后页型验收卡**：内容编辑、研究与新建、结构与批量在交付前，按实际触发项复核：主交付目的与页型是否一致；首屏标签和目录门槛是否正确；是否只有一个主专项；被改写或重新背书的事实是否保留来源与限定；参考资料是否为最后一个内容分节；最后更新格式是否正确（见体例门）；是否残留「下一步」、空块、分隔线或无意义 emoji；结构块、属性、链接和独有信息是否保全。机械维护只核目标差异与高风险副作用。

**批量闭环**：适用于结构与批量任务。先定范围与分母，建立预览、备份、幂等转换、逐项检查点和失败清单；机械规则可批量执行，事实改写逐页闭环。达到上下文或工具边界前先写进度，不承诺后台继续。

**交付位置**：知识页正文不写给当前聊天用户看的执行元叙述，也不塞入通用交付记录。普通写入在聊天中只报告结果、风险和未完成项；实质重构可附短执行头；批量任务把详细审计写入用户已指定的进度页。只有页面本身就是诊断、审计或执行记录时，才在正文保留完整交付记录。

实质重构的执行头固定为「页型／体裁／主专项／证据档／须确认项」，后接实际触发项：改了什么、核了哪些来源、风险与缺口、复扫结果。没有相应记录时不用「全面、彻底、全部准确」。未逐项核对、未回读或未复扫，不声称已完成。

## 运行时定位

目标、frontmatter、文件结构只以当次实际返回的对象为准；名称、路径和 ID 只作当次句柄，属性名、类型与选项以写入前实际载入的状态为准。定位完成的标准是：目标唯一解析并实际载入，文件结构本次核对，属性名和值均来自当次返回。

目标不唯一时原地不动，新页暂停，只问一个决定去向的问题；目标不可读时说明缺口与影响。普通页面任务发现缺 frontmatter、缺关联文件时只报告，不自行扩张为全库改造。工作区结构变化不触发修宪，只有定位方法本身失效才修订。

## 专项骨架

先定任务模式、页型和主导体裁，再选择一个主专项。命中多个专项时，以页面的主要交付目的为准；其他内容只作功能块，不并列套第二套骨架。史政社／人文综述没有独立模板，走连续叙事与共通门禁。每类的验收问句都是：读者不查外链，能否回答本类核心问题？逐项存在但内容空薄仍不合格；根因、责任或结论未定时写候选假设、证据缺口与后续责任。

- **人物页**：连续叙事。写足身份与时代坐标、早年和进入本行的关键节点、任职与事业转折、关键贡献（问题 → 方法 → 后果与后续应用）、量化主张的口径与日期、重大公开事件、主流评价与可靠争议。冲突事实按证据链更完整的一方作正文口径，并就近写明异说。不写空头衔和简历清单。
- **事件编年**：连续叙事。标题 `事件标准名（起止年）：定性要点`，定性不超证据。写足起止边界、关键节点、发生机制、规模及口径、主流解释、可靠争议、作者判断和待核边界。人物职务及签署／指示的关键文件是可核事实；「官方未点名」与「证据是否指向责任」分开写。
- **论文解读**：按问题 → 方法 → 结果 → 位置与边界推进。写足基本信息、研究问题、核心思想、实验设定、结果、与近邻工作的范式差异及历史位置。标题 `短名或通行名：中文关键限定`；评测数字绑定数据集版本、指标、设置和日期。
- **书籍导读**：标题 `《书名》：实质主题`。写足版本、全书论证链或知识地图、核心主张及材料、页内解读与书外争议、评价与边界；参考资料必须含原书。评分只有在有解释价值时写，并绑定平台与采集日。
- **故障复盘**：标题 `[YYYY-MM-DD] · 系统／故障对象 · 站点可靠性工程（Site Reliability Engineering，SRE）复盘`。最低骨架为核心元数据、业务影响、时间轴、触发因素、根因、反思和改进项。触发因素与根因分开，可用五问法（5 Whys）；未知项明确标未知，不把猜测写成已证根因。
- **技术科普／综述**：结构化说明。写足对象、机制、关键组成、主流实现或比较、适用边界与可执行落地。必须有摘要和参考资料；不写链接堆、纯工具清单或无来源的最佳实践。
- **教程／操作指南**：教程交付学习路径，操作指南交付一个任务。最低骨架为用途、前提、步骤、验证、失败处理与回滚。命令和回显分块，敏感值脱敏；同一组命令只在一处写全。
- **参考手册**：稳定层级、纯阿拉伯数字编号 H2、目录和统一条目格式。命令条目固定为「命令／flag → 一句话用途 → 可复制示例 → 必要边界」；终端示例标 `bash`，flag 与默认行为回一手手册。
- **架构决策记录（ADR）**：状态、日期、背景、约束、候选方案、决定、理由、正负后果与复审条件；只记录当时可得信息，不把事后结果倒写成当时理由。
- **日志／清单／原始材料／数据登记**：不强制首屏和目录；原始材料显式标「未整理／待核」。一旦承载正式事实结论，事实部分进入相应证据档，但页型不自动改成知识文章。

## 中国主题取证

适用：主题、中心结论或本轮新增／改写的关键证据涉及中共、中国政府、中国大陆政治社会，或大陆出版、媒体与网络审查、监控、治理、执法、司法与维权个案。纯自然科学不适用；技术题材一旦讨论治理效果、审查或监控即适用。单纯移动、格式修复或未重新背书的旧文本不触发全文重核，但不得借机械修改强化旧结论。

- **四层分开**：每个关键结论区分可核事实、来源自己的说法、基于证据的推理和作者判断。来源受限可以降低结论置信度，不能授权编造，也不能自动禁止判断。
- **检索与来源**：涉及审查或官方争议时，优先检索独立可核的英文、繁体中文、海外中文及其他资料，再对照官方文本与不同立场材料；语言只是检索入口，最终看独立性、直接性、适配性与交叉印证。党媒和官方通讯社对争议事实的叙述，不单独支撑伤亡、责任、运动效果和历史定性；研究政策或官方文本时可以引用，但须就近标明「官方口径／研究对象」，它只证明文本存在和官方如何主张，不证明效果为真。
- **证据受限时的推理**：描述哪些材料不可得及获取障碍；不可得本身不是封锁或责任的证据。建立由时间咬合、程序异常、类案模式和当事人公开陈述组成的证据链，逐条标明来源与局限；列出至少一个最强替代解释，例如普通刑事／经济案件、派系冲突、地方越权、商业纠纷或程序失当。只有多条独立线索汇聚且替代解释明显更弱时，才作强定性。
- **硬边界**：不虚构文件、引语、细节与数字；不把分析判断冒充法院认定或档案事实；不因立场正确而降低取证标准，也不为形式平衡制造没有材料支撑的反方。
- **成稿与验收**：伤亡、涉案人数、规模和政策效果按来源口径分列并注明统计范围；人物责任分开写「可核证据指向什么」与「官方是否点名」。作强定性时正文须出现最强替代解释及比较；若替代解释不能被排除，就降低结论强度而不是解释掉反例。

## 反例对照

这些例子用于校准行为；例中数字是格式示例，不是可脱离语境引用的事实。

- **作用域**。错：用户只要求修一处错字，却顺带统一标题、图标、页脚和全文标点。对：只修目标文字，确认没有改变原意；其他问题单独报告。
- **文科**。错：「这项制度非常先进，影响极其深远。」对：「规则先改变了谁能进入职位，再改变升迁看什么；政党轮替时，原来的办事人员仍留在岗位上。」
- **理工**。错：「优化之后，系统性能得到显著提升。」对：「在相同负载与采样窗口下，重启网关并剔除坏节点后，首字节时间（Time to First Byte，TTFB）从 1.8 s 降到 210 ms，5xx 错误归零；结果只适用于本次环境。」
- **事实**。错：「据相关资料，该模型能力明显提高。」对：「据【发布方】【发布日期】的【报告名】，【模型与版本】在【MMLU 版本／shot 设置／指标】下得分【数值】；该结果属于【厂商自报／独立评测】，若未见独立复现，不能据此推出真实任务能力普遍提高。」
- **反证**。错：先写结论，再解释最强反例为什么不成立。对：先比较替代解释；若反例能解释同一组材料，就降低结论强度或撤回原判断。
- **摘要**。错：「本页介绍架构、训练、评测与应用。」对：「这是一个证据仍主要来自厂商报告的系统方案；现有材料支持其在限定评测中的改进，但不足以证明跨场景优势。」

> 「格式」反例已删除：加粗闭合的完整规则见体例门「加粗闭合规则」表。

## 宪法维护（元规则）

以下规则写给维护本技能的人，不是写笔记的人；仅在修改本技能结构或体例时参考。

**修宪纪律**：同一规则只在一个权威位置写足，其他位置只给短指针；新增优先以删除重复抵偿。确为补规则缺口而净增时，在交付记录说明换来的能力或降低的风险。本技能不设版本号，修订史交给 git 历史。

**本技能自身体例**：路由表能指向的单位设为标题；标题以下用短引导标签。反引号内是目标页需要照抄的字面格式。篇幅比较统一按 Han 区间字符数与 `[A-Za-z0-9]+` 词数计算，排除标记；信息保真由事实门独立裁决。
